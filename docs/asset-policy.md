# Lucia2PC asset and data policy

## Core rule

**Proprietary game files and assets must not be stored in this repository.**
Lucia2PC is built and run locally using files supplied by the user. The same
rule applies to other titles used for testing and to other proprietary
material.

## Not allowed in the repository

This restriction applies to files, string literals, fixtures, snapshots and
documentation. It includes:

- Game assets: models, textures, shaders, audio, video, text and archives.
- The game executable or any part of it, including data sections, strings,
  tables, resources and code, except for the limited signatures described
  under the allowed section.
- Material derived from proprietary game content, including converted assets,
  decompiled or disassembled code, shader dumps, extracted tables and
  screenshots.

## Allowed

The repository may contain:

- Project-owned code that understands file and data formats.
- Build identities, such as a BLAKE3 hash of an executable or its CodeView
  GUID and age.
- Per-build offsets for hooked functions, under project-chosen names.
- Byte-pattern signatures used to locate functions or data in an executable.
- Small interoperability constants written by the project, such as magic
  numbers and enum values.
- Synthetic test data generated by project-owned code.

## Documented exception

`crates/victory-formats/src/bcpack-tables.bin` (approximately 78 KB) contains
constant tables for the BCPack format, including entropy models, index-rank
tables, control codes and per-format dictionaries.

The existing project policy records this as an exception in
`xtask/src/policy.rs`. The tables are required to decode BCPack streams and
cannot be derived by the project. The exception was recorded by the project
owner on 2026-11-23.

These tables are part of the format rather than project-authored material;
the repository's licence does not cover them. This is a specific, documented
exception, not permission to add other proprietary data.

## Where local data belongs

Game files and generated data belong outside the repository. The paths are
configured in `victory.toml`:

- `game_dir`: the user's local game files.
- `test_titles`: local title files used for testing.
- `cache_dir`: generated and converted data. The default is
  `%LOCALAPPDATA%\victory\cache`.

## Enforcement

1. `.gitignore` excludes common data types from ordinary `git status` output.
2. `cargo xtask policy` checks the repository using an allowlist. The check
   runs through the pre-commit hook, installed with
   `cargo xtask install-hooks`.
3. Files must use an allowed type, be smaller than 512 KiB, contain no binary
   data or known binary signatures, and contain no long hexadecimal or
   Base64-like runs. An exception requires a reason recorded in
   `xtask/src/policy.rs`.
4. At runtime, code that writes derived data calls
   `victory_core::ensure_outside_repo`.
5. Tests that require real files obtain their paths from environment
   variables and skip when those variables are unset. Tests should assert
   properties, not compare proprietary snapshots.

## If prohibited material is committed

Removing the file in a later commit is not sufficient because the content
remains in Git history. Rewrite the affected history (for example, with
`git filter-repo --path <file> --invert-paths`), force-push the corrected
history, and have collaborators re-clone the repository.
